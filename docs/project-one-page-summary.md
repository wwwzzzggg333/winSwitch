# mySwitcher 一页纸摘要

## 1. 项目一句话

`mySwitcher` 是一个基于 Qt 6 的跨平台桌面窗口切换管理器，目标是在 Windows、macOS、Linux 上提供统一的窗口切换体验。

## 2. 当前状态

- Windows：接近完整可用，已具备较强实用价值
- macOS：基础支持，能浏览和基础切换，但关键能力缺失较多
- Linux X11：基础支持，能列窗口和切换，但热键等主入口未补齐
- Linux Wayland：受平台安全模型限制，很多能力无法作为普通应用直接实现

一句话判断：

- 当前项目已经具备继续投入的基础，但离“真正跨平台可日常使用”还有明显差距

## 3. 当前已经具备的核心能力

- 托盘常驻
- 单实例运行
- 枚举窗口并按应用分组
- 点击或键盘方式激活窗口
- 关闭单窗口和整组窗口
- 置顶应用
- 排除应用
- 缩略图和图标的基础展示
- 设置持久化

## 4. 目前最明显的短板

- 没有关键字搜索
- 没有最近使用排序
- 多屏幕体验不足
- 热键体系不完整
- macOS 和 Linux X11 仍缺主入口能力
- Wayland 下很多功能受平台机制限制

## 5. 平台差异结论

### Windows

- 当前最成熟
- 最适合优先打磨成标杆版本

### macOS

- 目前更像“基础版”
- 热键、关闭窗口、精确窗口控制仍需补齐

### Linux X11

- 目前能做基础窗口切换
- 但缺少热键，闭环不完整

### Linux Wayland

- 很多限制不是代码没写，而是平台默认不允许
- 适合采用“明确降级，不做强承诺”的策略

## 6. 最值得优先投入的方向

### 第一优先级

- 关键字搜索
- 最近使用排序
- 多屏幕感知显示

原因：

- 对所有平台都有价值
- 用户感知最直接
- 风险相对可控

### 第二优先级

- macOS 全局热键
- macOS 关闭窗口
- Linux X11 全局热键
- 平台能力诊断页

原因：

- 这些是跨平台主流程闭环的关键缺口

## 7. 哪些能力受平台限制，无法统一保证

- 完整全局窗口列表
- 稳定全局热键
- 任意窗口缩略图抓取
- 任意第三方窗口精确控制
- 文件管理器窗口真实路径解析
- 关闭整组窗口

核心原因：

- Windows、macOS、Linux X11、Wayland 的窗口模型和权限模型差异很大
- 其中 Wayland 对跨应用观察和控制限制最强

## 8. 建议产品策略

不要追求“四个平台完全一致”，而应采用：

- 核心体验统一
- 平台能力分级
- 不可用能力显式提示
- 高限制平台做降级支持

更具体地说：

- Windows：做完整体验
- macOS：补权限相关能力，逐步增强
- Linux X11：补齐热键和兼容性
- Wayland：明确限制，重点做检测和说明

## 9. 推荐版本节奏

### v0.2

- 做强体验
- 补搜索、MRU、多屏和诊断

### v0.3

- 补齐跨平台主流程
- 重点补 macOS 与 Linux X11 缺口

### v1.0

- 做稳定发布版
- 完善文档、降级策略和产品化能力

## 10. 汇报版结论

如果要用于管理视角汇报，可以直接表述为：

- 这个项目方向正确，Windows 端已有较强落地价值
- 当前最值得投入的是搜索、最近使用排序和多屏支持
- 跨平台真正的主要挑战在 macOS 权限能力和 Linux/Wayland 平台限制
- 后续应该采用“Windows 做强、macOS/Linux 分阶段补齐、Wayland 明确降级”的推进策略
