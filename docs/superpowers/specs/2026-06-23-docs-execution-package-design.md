# mySwitcher 文档执行包设计说明

## 1. 背景

当前项目已经补充了多份分析与规划文档，包括：

- 项目功能与平台限制分析
- 功能优先级与投入分析
- 开发路线图
- 文档索引
- 一页纸摘要

下一步目标不是继续做泛化分析，而是补齐两类更适合开发落地的文档：

1. 一份偏正式规格的执行型产品方案
2. 一份面向 `v0.2` 的工程任务拆解文档

这两份文档需要服务“开发执行”场景，而不是单纯的汇报展示。

## 2. 目标

本次文档执行包的目标是：

- 把现有结论沉淀为可执行的规格文档
- 明确 `v0.2` 的范围、边界、非目标和验收标准
- 把 `v0.2` 的工作拆解到模块和任务层级
- 让开发可以直接据此开始排期、拆任务和实施

## 3. 目标读者

主要目标读者：

- 开发负责人
- 具体执行开发
- 需要对齐范围和验收口径的产品/项目协作方

次级目标读者：

- 需要快速了解开发准备程度的管理者

## 5. 总体设计原则

### 5.1 强执行型

文档写法采用“强执行型”而不是“纯汇报型”。

要求：

- 语言尽量明确，不写空泛目标
- 每项能力都尽量写清楚“做什么、不做什么、为什么、如何验收”
- 尽量把功能描述转化为可实施的条目

### 5.2 聚焦 v0.2

本轮文档重点聚焦 `v0.2`，不试图把所有后续版本内容一次写完。

### 5.3 低风险高收益优先

`v0.2` 只纳入低风险高收益、跨平台一致性较好的能力。

不把高平台风险特性放进本轮实施正文。

### 5.4 平台能力分级

文档中必须明确：

- 哪些能力是全平台共性能力
- 哪些能力是平台增强能力
- 哪些能力受平台机制限制，只能降级支持

## 6. v0.2 范围定义

### 6.1 纳入范围

本次 `v0.2` 执行范围包含以下 6 个主题：

1. 搜索能力
2. 最近使用排序（MRU）
3. 多屏幕感知
4. 热键增强
5. 平台能力诊断页
6. 配置导入导出

### 6.2 不纳入范围

以下内容不进入本轮 `v0.2` 正文实施范围：

- macOS 全局热键实现
- macOS 关闭窗口实现
- Linux X11 全局热键实现
- Wayland 深度适配
- 更复杂的窗口管理能力
- 大规模 UI 风格重做

这些内容可以在文档中作为后续版本依赖或扩展项出现，但不作为 `v0.2` 交付承诺。

## 8. 六个 v0.2 主题的设计要点

### 8.1 搜索能力

目标：

- 让用户在切换面板中快速定位窗口

范围：

- 支持按窗口标题搜索
- 支持按应用名搜索
- 支持按路径搜索
- 搜索结果实时刷新

非目标：

- 暂不做复杂自然语言搜索
- 暂不做跨语言语义检索

关键设计点：

- 搜索与现有应用分组如何协同
- 搜索结果是否仍保留分组结构
- 是否高亮匹配文本

### 8.2 最近使用排序

目标：

- 让切换顺序更符合真实使用习惯

范围：

- 记录窗口激活时间
- 支持按最近使用排序
- 与当前置顶应用规则协同

非目标：

- 暂不做复杂权重模型

关键设计点：

- 置顶优先和 MRU 优先的先后关系
- 应用级排序和窗口级排序的联动方式

### 8.3 多屏幕感知

目标：

- 让面板显示位置更符合多屏使用习惯

范围：

- 跟随鼠标所在屏幕显示
- 预留跟随前台窗口所在屏幕的策略

非目标：

- 暂不做复杂的跨屏面板联动

关键设计点：

- 如何获取当前目标屏幕
- 当获取失败时的回退策略

### 8.4 热键增强

目标：

- 改善热键配置和失败可解释性

范围：

- 扩大热键录入支持范围
- 增加冲突或失败提示
- 增加平台差异提示

非目标：

- 不在 `v0.2` 中补齐所有平台的热键底层实现

关键设计点：

- 录入能力与后端解析能力保持一致
- 对不支持的平台给出明确说明

### 8.5 平台能力诊断页

目标：

- 让用户和开发快速判断当前环境支持哪些能力

范围：

- 展示当前平台
- 展示会话类型
- 展示热键支持状态
- 展示缩略图支持状态
- 展示图标支持状态
- 展示日志路径

非目标：

- 不做复杂性能诊断
- 不做远程上报

### 8.6 配置导入导出

目标：

- 提高配置迁移与备份能力

范围：

- 导出当前配置
- 导入配置文件
- 基础格式校验

非目标：

- 不做云同步
- 不做多设备配置中心

## 9. 风险与约束

### 9.1 范围失控风险

如果把平台高风险能力一并纳入 `v0.2`，会导致版本目标发散。

控制策略：

- `v0.2` 只做低风险高收益能力
- 平台高风险项只写入后续版本依赖

### 9.2 交互复杂度风险

搜索、分组、置顶、MRU 一旦同时改动，交互逻辑容易产生歧义。

控制策略：

- 在规格中明确排序和过滤优先级
- 避免同一版本引入过多可切换策略

### 9.3 平台理解偏差风险

用户可能把“未实现”和“平台本身不支持”混淆。

控制策略：

- 在产品方案和诊断页中明确区分
- 给出清晰提示语和降级说明

## 10. 验收口径

本次文档输出完成后，应满足以下标准：

- 两份文档可以被开发直接阅读并开始拆任务
- 文档中明确了 `v0.2` 的范围和非目标
- 文档中明确了平台限制和降级策略
- 文档中每个任务主题都有相对清晰的完成标准

## 11. 后续流程

本设计说明确认后，下一步应进入：

1. 写出正式产品方案文档
2. 写出 `v0.2` 开发任务拆解文档
3. 在此基础上再继续细化实现计划

本设计说明不直接承担实现，而是作为这两份文档的上游规格。
