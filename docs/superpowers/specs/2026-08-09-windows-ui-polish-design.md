# mySwitcher Windows 界面轻量修整设计

## 1. 背景

当前 mySwitcher v0.2.0 在 Windows 11 上已经具备搜索、应用筛选、窗口分组、缩略图、图标和窗口操作等主流程能力，但界面仍存在几项明显问题：

- 原生浅色标题栏与深色内容区域割裂。
- 默认面板在低分辨率屏幕上接近铺满可用区域。
- 缩略图抓取失败时只显示很小的应用图标，卡片出现大面积黑色空区。
- 顶部筛选条高度紧张，项目多时横向滚动不够自然。
- 没有窗口或搜索无结果时，内容区只有空白。
- 字体、间距、卡片状态和次要信息层级仍显得偏工具原型。

用户已选择“A：轻量修整”方向：保留现有搜索、横向应用筛选、分组标题和卡片网格，不引入应用侧栏，不进行大规模结构重写。

## 2. 目标

本轮目标是在不改变核心交互模型的前提下，修复 Windows 11 上最明显的视觉和状态问题：

1. 让标题栏与深色主题协调。
2. 让面板在低分辨率和多屏环境中始终保留合理边距。
3. 让缩略图不可用状态可理解且视觉完整。
4. 让筛选条、分组标题和卡片的信息层级更清楚。
5. 为窗口为空和搜索无结果提供明确状态。
6. 建立最小 Qt Test 基线，为后续功能迭代提供测试入口。

## 3. 非目标

本轮明确不做：

- 不改为左侧应用导航或其他全新布局。
- 不改变窗口枚举、搜索匹配、MRU 或平台抓图算法。
- 不重写 `SwitcherPanel` 为 Model/View 架构。
- 不增加整组关闭确认。整组关闭继续直接执行，这是用户确认的产品行为。
- 不在本轮处理 `WM_CLOSE` 被拒绝、延迟关闭或失败反馈；这些属于后续“操作状态同步”功能。
- 不实现 macOS/Linux 的原生标题栏适配。
- 不引入动画系统、主题切换或第三方 UI 库。

## 4. 设计方案

### 4.1 Windows 深色标题栏

在 `MainWindow` 创建原生窗口后，Windows 构建通过 `DwmSetWindowAttribute` 请求沉浸式深色标题栏：

- 优先使用 `DWMWA_USE_IMMERSIVE_DARK_MODE` 属性值 20。
- 必要时回退旧属性值 19。
- 调用失败只写警告日志，保留系统默认标题栏，不阻止程序启动或显示面板。
- 代码使用 `#if defined(Q_OS_WIN)` 隔离；其他平台不改变行为。

窗口标题、最小化、最大化和关闭按钮继续使用原生系统控件。本轮不采用无边框自绘标题栏，以避免拖动、缩放、DPI、辅助功能和多屏行为回归。

### 4.2 面板尺寸约束

将面板尺寸计算抽成可测试的纯函数，输入为当前屏幕可用尺寸和配置尺寸，输出最终面板尺寸。

规则：

- 默认目标仍接近当前 70% 宽、62% 高的体验。
- 最终宽高不得超过屏幕可用区域减去四周安全边距。
- 安全边距建议每侧至少 24px；小屏幕优先保证窗口完整可见，而不是坚持 840×540 的旧最小值。
- 配置中的 `panel_width`、`panel_height` 仍作为期望尺寸，但必须被当前屏幕上限约束。
- 保留合理的最低可用尺寸；屏幕本身小于最低值时，以实际可用空间为准。
- 面板仍显示在鼠标所在屏幕中央。

建议新增 `src/ui/UiSizing.h/.cpp`，提供不依赖 QWidget 的尺寸计算函数，便于单元测试。

### 4.3 缩略图不可用占位

`WindowCard` 继续保持现有卡片结构和 16:9 预览区域，但完善三种显示状态：

1. 有缩略图：按现有方式裁切并填充预览区。
2. 无缩略图但有图标：显示 56～64px 应用图标，并在下方显示“窗口预览不可用”。
3. 缩略图和图标都不可用：显示统一窗口占位图形及同一提示。

占位区域使用略浅于当前黑底的中性渐变或纯色表面，保持足够对比度，不使用错误红色，因为这通常是平台能力限制而非致命错误。

新增中英文 i18n 文案：

- 中文：`窗口预览不可用`
- 英文：`Preview unavailable`

当用户在设置中主动关闭缩略图时，卡片可以只显示应用图标，不显示“不可用”提示，避免把用户选择误报为失败。因此 `WindowCard` 需要知道“缩略图功能已关闭”和“功能开启但本窗口没有结果”的区别。

### 4.4 空状态

`SwitcherPanel::rebuildContent()` 在构建分组前判断可见组：

- 所有窗口为空且搜索词为空：显示“当前没有可切换窗口”。
- 搜索词非空且没有匹配：显示“没有匹配的窗口”，并保留顶部搜索框的清除按钮。

空状态包含一个低强调图标、主文案和简短说明，不增加额外按钮。空状态控件使用稳定的对象名，便于 UI 测试和 QSS 定位。

新增中英文 i18n 文案：

- `当前没有可切换窗口` / `No switchable windows`
- `没有匹配的窗口` / `No matching windows`
- `尝试打开一个窗口，或检查排除应用设置。` / `Open a window or check the excluded-app settings.`
- `请尝试其他关键词。` / `Try a different search term.`

### 4.5 顶部筛选条

保留横向筛选 chip 和每个应用的关闭入口，不改变整组关闭行为。

视觉和输入调整：

- 适当增加筛选区高度，避免横向滚动条挤压 chip。
- 统一 chip 的内边距、圆角和选中状态。
- `×` 关闭按钮降低默认视觉权重，悬停时再显示危险色。
- 鼠标滚轮位于筛选区时转换为横向滚动，触摸板原生横向滚动继续有效。
- “全部”保持高强调选中态；应用筛选保持单行省略或固定最大宽度，避免超长名称占满整行。

不会增加“更多”下拉菜单，也不会移除筛选 chip 中的关闭按钮。

### 4.6 分组标题与卡片

保留分组头部左侧标题、右侧“置顶/关闭全部”结构，只做轻量层级调整：

- 应用名为主要文本，窗口数量为次要文本。
- 分组之间增加稳定间距，减少标题与上一组卡片粘连。
- “置顶”使用普通次要按钮；已置顶状态使用强调描边。
- “关闭全部”保留直接操作，默认保持次要样式，悬停时显示危险色。
- 卡片标题保持单行省略和完整 tooltip；路径保持次要颜色。
- 选中卡片使用清晰但不导致内容跳动的固定边框宽度。
- 统一字体为 Windows 友好的 `Microsoft YaHei UI` / `Segoe UI` 回退组合。

### 4.7 状态与数据流

本轮不引入新的业务状态机：

```text
ApplicationController
  -> AppState + icon/thumbnail cache
  -> MainWindow::showPanel
  -> SwitcherPanel::setData
  -> WindowCard(thumbnailEnabled, thumbnail, icon)
```

空状态直接由 `AppState::visibleGroups()` 和 `searchText` 派生。缩略图状态由 `thumbnailEnabled`、缩略图是否为空和图标是否为空派生，不增加持久化字段。

## 5. 代码影响范围

预计修改：

- `src/ui/MainWindow.cpp`：深色标题栏、使用新的尺寸计算函数。
- `src/ui/SwitcherPanel.cpp/.h`：空状态、筛选区滚轮和轻量布局调整。
- `src/ui/WindowCard.cpp/.h`：缩略图启用状态、占位显示、稳定对象名。
- `src/ui/UiSizing.h/.cpp`：纯尺寸计算函数。
- `src/core/I18n.h/.cpp`：新增中英文状态文案。
- `resources/styles/app.qss`：字体、筛选条、空状态、占位、按钮和卡片细节。
- `CMakeLists.txt`：登记 `UiSizing.cpp` 和测试目标。
- `tests/test_ui_sizing.cpp`：尺寸计算单元测试。
- 可选 `tests/test_window_model.cpp`：为空状态提供模型边界回归测试；若只测试既有 `visibleGroups()`，不引入 QWidget 依赖。

不会修改平台窗口枚举、缩略图抓取和窗口关闭实现。

## 6. 错误处理

- DWM 深色标题栏失败：记录日志并回退系统标题栏。
- 屏幕对象不可用：使用现有 1920×1080 回退尺寸，再应用安全约束。
- 图标和缩略图均为空：显示通用占位，不抛异常。
- 筛选条滚动范围为零：忽略滚轮转换，让事件继续按 Qt 默认流程处理。
- UI 重建过程中继续遵守现有 `deleteLater()` 策略，避免恢复此前 `clearLayout` 崩溃问题。

## 7. 测试方案

### 7.1 自动化测试

使用 Qt Test 建立首个测试目标，至少覆盖：

- 1920×1080、1280×720、超小可用区域和 4K 屏幕的尺寸计算。
- 配置尺寸小于、等于和大于屏幕上限。
- 输出尺寸永远不超过安全区域，且不为负数或零。
- `AppState::visibleGroups()` 在无窗口、无匹配和有匹配时的结果。

### 7.2 手工界面回归

- Windows 11 标题栏在系统浅色/深色主题下与应用深色内容协调；DWM 失败时仍可用。
- 1280×720、1920×1080、2560×1440 和不同 DPI 下，面板四周有边距且不超出工作区。
- 有缩略图、无缩略图有图标、两者皆无、用户关闭缩略图四种卡片状态正确。
- 无窗口、搜索无结果和正常结果状态切换正确。
- 大量应用筛选项可用滚轮横向浏览，关闭按钮仍可点击。
- 置顶、关闭单窗口、关闭全部、搜索、方向键和 Enter/Esc 行为无回归。
- 快速重复唤出和纹理批量更新不会触发 `clearLayout` 崩溃。

## 8. 验收标准

1. Windows 11 标题栏与深色主题一致，失败时安全回退。
2. 面板在常见分辨率下完整位于当前屏幕可用区域内，并保留安全边距。
3. 缩略图不可用不再表现为小图标悬在大片纯黑区域。
4. 空窗口和搜索无结果都有明确提示。
5. 顶部筛选项较多时可自然横向滚动。
6. 现有布局和主交互不变；整组关闭不增加确认。
7. 新增 Qt Test 目标通过，Release 构建通过。
8. 中文和英文新增文案完整，无用户可见硬编码。

## 9. 后续功能分类顺序

完成本轮界面轻量修整后，后续按以下类别继续：

1. **稳定性与测试**：扩大 core 测试、配置原子写入、缓存生命周期、日志轮转。
2. **操作状态同步**：关闭后重新枚举、失败反馈、激活结果；整组关闭仍不弹确认。
3. **性能与纹理管线**：异步抓图、取消、超时、缓存刷新和 HWND 重用防护。
4. **配置与诊断**：面板尺寸入口、诊断包、能力等级校准。
5. **产品化与跨平台**：安装签名、自动启动，以及 macOS/Linux 能力闭环。
