# winSwitch 功能优先级与投入分析

## 1. 文档目的

这份文档用于把 `winSwitch` 的候选功能整理成更适合讨论排期和资源投入的形式。

重点回答四个问题：

1. 哪些功能最值得优先做
2. 哪些功能对用户价值最高
3. 哪些功能实现难度和风险较大
4. 哪些功能受平台限制，不适合过早承诺

本文中的判断结合了当前代码实现状态、平台差异和跨平台桌面应用的一般限制。

## 2. 评估标准

### 2.1 优先级定义

- `P0`：强烈建议优先投入，能直接改善主流程可用性
- `P1`：建议尽快投入，能显著提升核心体验
- `P2`：有价值，但不是短期上线的阻塞项
- `P3`：偏增强或长期项，可在核心闭环稳定后推进

### 2.2 收益定义

- `高`：直接影响日常使用效率或可用性
- `中`：明显改善体验，但不是决定性因素
- `低`：提升有限，更多是锦上添花

### 2.3 难度定义

- `低`：主要是界面或模型层改造
- `中`：涉及多模块联动或单平台底层能力扩展
- `高`：涉及跨平台底层适配、权限、协议或稳定性问题

### 2.4 风险定义

- `低`：实现边界清晰，回归风险可控
- `中`：平台差异、性能或交互设计存在不确定性
- `高`：高度依赖系统能力、权限模型或桌面环境差异

## 4. 推荐优先级解读

### 4.1 第一梯队：最值得马上做

#### 4.1.1 面板关键字搜索

优先级：`P0`

建议原因：

- 当前只有按应用分组过滤，没有实时搜索，实际效率不够高
- 搜索是用户最容易感知价值的增强项
- 搜索逻辑主要发生在 UI 和模型层，跨平台一致性好
- 不依赖底层窗口协议增强，投入产出比很高

建议细化：

- 支持窗口标题搜索
- 支持应用名搜索
- 支持路径搜索
- 支持结果高亮
- 支持中文拼音或首字母匹配

#### 4.1.2 最近使用排序

优先级：`P0`

建议原因：

- 用户对切换器的核心预期不是“静态列表”，而是“快速回到刚刚用过的窗口”
- MRU 是窗口切换工具体验差异最大的能力之一
- 主要是状态维护和排序规则改造，技术风险不高

建议细化：

- 记录窗口激活时间
- 记录应用组最近活跃时间
- 允许在“置顶优先”和“最近使用优先”之间切换

#### 4.1.3 多屏幕感知

优先级：`P0`

建议原因：

- 当前面板默认居中到主屏幕，在双屏和三屏环境中体验偏弱
- 多屏支持能直接改善使用者的主流程感受
- 实现复杂度相对可控，不需要大量平台底层扩展

建议细化：

- 跟随鼠标所在屏幕显示
- 跟随当前前台窗口所在屏幕显示
- 允许在设置中选择显示策略

### 4.2 第二梯队：补齐核心可用性差距

#### 4.2.1 macOS 全局热键

优先级：`P1`

建议原因：

- 没有全局热键时，macOS 只能依赖托盘入口，使用闭环不完整
- 这是 macOS 从“基础支持”走向“可日常使用”的关键功能

风险提醒：

- 涉及系统接口和权限
- 需要处理热键注册失败、冲突和权限提示

#### 4.2.2 macOS 关闭窗口

优先级：`P1`

建议原因：

- 关闭窗口是当前功能矩阵中的明显缺口
- 若不支持关闭单窗和整组，macOS 版本与 Windows 体验差距会持续很大

风险提醒：

- 可能需要 Accessibility API 或 AppleScript
- 对权限、系统版本和应用兼容性敏感

#### 4.2.3 Linux X11 全局热键

优先级：`P1`

建议原因：

- Linux X11 目前虽然能列窗口和切换，但缺少热键导致主入口不完整
- 补上后可以至少形成“可用但有限”的基础体验

风险提醒：

- 不同桌面环境和窗口管理器兼容性差异较大

#### 4.2.4 平台能力诊断页

优先级：`P1`

建议原因：

- 跨平台项目最怕“用户以为是 bug，其实是平台不支持”
- 诊断页可以明确显示当前系统支持哪些能力
- 也适合把权限状态、Wayland/X11 状态、热键注册状态展示出来

建议展示项：

- 当前平台与会话类型
- 热键是否支持
- 缩略图是否支持
- 图标是否支持
- 是否需要系统权限
- 当前日志路径

### 4.3 第三梯队：增强实用性和完成度

#### 4.3.1 更多窗口操作

优先级：`P2`

建议原因：

- 会让产品从“切换器”进一步走向“轻量窗口管理器”
- 但它不是当前主流程最紧急的缺口

建议功能：

- 最小化
- 恢复
- 关闭其他窗口
- 最小化其他窗口

#### 4.3.2 图标获取补齐

优先级：`P2`

建议原因：

- 对视觉识别帮助很大
- 当缩略图不可用时，图标是很重要的降级方案

风险提醒：

- 平台上的“窗口图标”和“应用图标”语义不完全一致

#### 4.3.3 配置增强

优先级：`P2`

建议原因：

- 导入导出配置、开机自启动、日志页等功能成本相对可控
- 能明显提升产品成熟度

### 4.4 第四梯队：长期项和策略项

#### 4.4.1 Wayland 深度适配

优先级：`P3`

建议原因：

- 很重要，但这不是一个单纯的“开发排期”问题
- 受 Wayland 安全模型和桌面环境差异影响非常大
- 更适合作为长期探索项和能力降级项，而不是短期版本承诺

建议方向：

- 研究 portal
- 研究 GNOME/KDE 扩展可能性
- 明确文档和 UI 中的降级提示

## 5. 风险最高的功能

下面这些功能需要谨慎承诺：

| 功能 | 风险等级 | 风险来源 |
|------|----------|----------|
| macOS 关闭窗口 | 高 | 依赖权限、辅助功能接口、系统行为差异 |
| macOS 精确聚焦某个窗口 | 高 | 应用激活与窗口聚焦不是同一层级能力 |
| Linux Wayland 全局热键 | 高 | 普通客户端通常没有统一可用方案 |
| Linux Wayland 窗口枚举 | 高 | 平台安全模型默认限制 |
| Linux Wayland 缩略图抓取 | 高 | 普通应用一般不能读取其他窗口内容 |
| 跨平台统一文件管理器路径解析 | 高 | Explorer、Finder、各类 Linux 文件管理器接口差异很大 |

## 6. 适合尽快交付的“低风险高收益”功能

下面这些功能最适合优先排期：

| 功能 | 收益 | 难度 | 原因 |
|------|------|------|------|
| 关键字搜索 | 高 | 中 | 直接提升效率，跨平台一致性最好 |
| 最近使用排序 | 高 | 中 | 更符合切换器使用习惯 |
| 多屏幕感知显示 | 高 | 中 | 多显示器用户收益极高 |
| 平台能力诊断页 | 中 | 低 | 很适合跨平台产品，交付风险低 |
| 导入导出配置 | 中 | 低 | 成本低，提升成熟度明显 |
| 热键冲突提示 | 中 | 低 | 可以快速提升可用性和可解释性 |

## 7. 建议资源投入顺序

如果按有限资源推进，建议顺序如下：

### 阶段一：先把主流程体验做强

1. 关键字搜索
2. 最近使用排序
3. 多屏幕感知
4. 热键体系增强

### 阶段二：补齐跨平台主要缺口

1. macOS 全局热键
2. macOS 关闭窗口
3. Linux X11 全局热键
4. 平台能力诊断页

### 阶段三：增加成熟度和产品感

1. 更多窗口操作
2. 图标能力补齐
3. 配置导入导出
4. 开机自启动
5. 日志与诊断增强

### 阶段四：长期探索

1. Wayland 深度适配
2. 文件管理器路径增强
3. 更深入的权限引导与平台集成

## 8. 汇报版结论

如果把这份分析压缩成适合汇报的结论，可以概括为：

- 这个项目当前最适合先把 Windows 体验打磨成标杆版本
- 中短期最值得投入的是搜索、最近使用排序和多屏支持
- macOS 与 Linux X11 的重点是补齐热键和基础控制能力
- Wayland 相关能力属于平台强限制问题，不应作为短期版本强承诺
- 产品策略上应采用“核心体验统一，平台能力分级”的路线
